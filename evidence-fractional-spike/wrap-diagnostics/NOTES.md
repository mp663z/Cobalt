# Wrap flip diagnostics (UNREVIEWED; hypotheses tested, none adopted)
Traced case: Liberation Sans 12 px (integer), container 160.109375 px, kerning off. NOTE flip-trace.txt columns "chrome isolated" and the "chrome space" line are INVALID (the probe span was not in the test font family); use only the in-flow span widths and line widths.
Facts: in-flow word widths in Chrome exceed the fontdue unrounded sum by 0.000..0.0137 px and are all multiples of 1/64 (for the traced words equal to the sum rounded UP to 1/64); used width of the five full lines exceeds the model by 0.039..0.092 px, so Chrome lines are slightly wider than the model, which makes Chrome break earlier in some cases and, in others, later (the 17 grid flips go both ways).
Hypotheses tested on the full 1173-case wrap grid (all refuted as improvements over the baseline 17 flips): (B) ceil each word and space to 1/64: 25 flips; (C) one-step used-size lag at k%16==1 (from a plateau seen in Liberation Sans H widths: authored q+1/64 renders like q at q = 12, 12.25, ... 14.75): 16 flips, only one grid size is affected so it cannot explain the rest; (D) round each glyph advance to 1/64 then sum: 21 flips; (E) ceil each glyph advance: 37 flips. The cause of the remaining flips is not located.
Side observation (effsize-summary.txt): 1000 x H width vs authored size k/64 in 12..15 px is linear except 12 of 192 steps where the next 1/64 size gives an identical width (then a double step), at every quarter-pixel authored size 12, 12.25, ..., 14.75; so authored q+1/64 appears to render like q. Single face; not tested elsewhere.
