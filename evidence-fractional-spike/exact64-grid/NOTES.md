# Exact 1/64-multiple size grid (UNREVIEWED measurement)
Chrome 156.0.8078.47, embedded Liberation Serif, DejaVu Sans, Liberation Sans (pinned). Authored sizes k/64 px for k = 512..2560 step 7 (293 sizes per font, 879 rows), strings: 'The quick brown fox jumps over the lazy dog 0123456789' (55 chars, kerning none), line-height normal and 1.5.
Results (exact64-compare.txt): unitless 1.5 line-height equals floor(size*1.5*64)/64 on 879/879 rows (max |used - 1.5*size| = 0.0078). Normal line height equals round(asc)+round(|desc|)+round(gap) on 875/879; misses: Liberation Serif 26.375 (Chrome 30, model 31); DejaVu 13.46875 (15 vs 16) and 35.015625 (40 vs 41); Liberation Sans 34.796875 (39 vs 40). Always model one higher than Chrome, so the round-sum rule is not exact at 1/64-multiple sizes either. Width of the 55-char string vs the fontdue unrounded advance sum: max residual 0.3676 (Liberation Serif), 0.4568 (DejaVu), 0.4002 (Liberation Sans) px, larger than the 0.2 seen on short strings, i.e. the residual grows with string length and is not geometry identity.
Consequence: no exact claim for normal line height or string width, even at exact 1/64 sizes; line-height as a unitless number at exact 1/64 sizes matched floor-to-1/64 on this grid. A prototype may state these as bounded approximations only (height +-1 px on normal, width within the measured residual) with refusal outside the measured faces/range.
